# Cache Lab
## 实验简介
本实验包含两部分，第一部分为编写一个高速缓存模拟器，第二部分为优化矩阵转置的缓存性能
## 主要文件
- -csim.c  缓存模拟器程序源代码，该程序维护一个参数为（组数S，每组行数E，每行容量B字节）的模拟的组相联高速缓存，解析valgrind程序生成的内存访问trace，输出：
  - hits：命中次数
  - misses：未命中次数
  - evictions：缓存行替换次数

- -trans.c  优化的矩阵转置程序，采用分块的技术针对32x32、64x64和61x67矩阵的特殊优化
## 第一部分
p.s 由于作者学习这一章时已经沉入底层无法自拔，甚至忘记了可以使用struct实现，最终以一种比较复杂的、直接使用整块内存方式实现，详细注释和说明见csim.c

### 程序结构
- main(int argc.char*argv[]) 解析命令行参数，解析统计返回的缓存命中情况
- initcache(int s,int E,int b) 根据s,E,b参数分配内存建立模拟缓存
- operate(int mode,unsigned long addr) 使用缓存模拟器模拟一次内存操作，返回命中情况
### 说明
- 缓存行结构为：8字节tag，B字节数据（本实验其实不需要读写数据，只需记录命中情况），1字节有效位，1字节LRU计数器
- 使用-v参数使模拟器每次操作都输出一个命中情况，使用-s [参数] -E [] -b []指定缓存组数、行数和每行容量

## 第二部分
分别对32x32，64x64，61x67做转置优化

### 说明
实验使用s,E,b参数为5,1,5的模拟缓存，即32组，每组1行，每行32字节，矩阵元素类型为int，程序将A矩阵转置后存入另一个矩阵B，两个矩阵连续的存储在内存中
### 32x32
缓存总容量是矩阵大小的1/4，正好装下矩阵的8行

仅在对角线块处，两个块会映射到同一组，是冲突不命中的主要来源

由于每个缓存行可容纳8个int，于是想到可以对矩阵进行8x8分块，每次读8个元素、写8个元素，减少冲突造成的重复加载和不命中
### 64x64
与32x32不同，缓存只能装下4行，每4行之间会产生缓存冲突，因此可以对8x8的块再划分成4x4

此时的优化方向是：
- 每次只读4个元素，但缓存一次加载8个，可以暂存利用
- 对对角线块，每次加载B只能写入1个元素，应该提高使用率

解决方案：使用临时变量读取后4个元素，提高读缓存命中率，又注意到写入b左上4x4块时，右上块也被载入缓存，利用这些空间暂存读取的a右上块的转置，详见代码和注释

### 61x67
需要理解：缓存组映射被打乱，有利于减少缓存冲突不命中，因此直接暴力分块即可，只需注意边界条件细节
